# Тесты системы: лестница по цене

Правило: дорогое запускается последним. Реальные задачи тестами не служат.

| Ступень | Что | Цена | Когда |
| --- | --- | --- | --- |
| 0 | `python3 scripts/selftest.py` — скрипты, форматы, фикстуры, генератор полигона | 0 токенов | после любой правки в `scripts/`, `.claude/`, `methodology/` |
| 1 | `scripts/polygon.py` — выдуманные отчёты об экспериментах с ключом ответов, сверка навыка | 0 на генерацию, один вызов навыка (около 90 тыс.) | менялся `experiment-review` или модуль Э |
| 2 | один навык на готовых артефактах фикстуры (`scripts/fixture.py`) | один вызов (60–90 тыс. на средней модели) | менялся именно этот навык |
| 3 | вся цепочка на выдуманной задаче | порядка 250 тыс. на «разбор», в 3–4 раза больше на «план проверки» | перед слиянием крупных правок |

Замеры на выдуманной задаче со средней моделью: диспетчер 85 тыс., разбор материалов 77 тыс., консультант 86 тыс. токенов. Вход крошечный (два файла по 1 КБ), поэтому почти вся цена — загрузка инструкций исполнителя. Тест навыка на фикстуре убирает первые два шага из трёх.

## Как тестировать один навык

1. Развернуть фикстуру до шага, предшествующего проверяемому навыку:

   ```
   python3 scripts/fixture.py make light --task tasks/_fx-1 --upto knowledge
   ```

   Шаги: `tz` (ТЗ и контекст), `knowledge` (+ карта знания), `review` (+ разбор консультанта).
2. Вызвать навык подагентом по шаблону вызова оркестратора (`.claude/skills/orchestrator/SKILL.md`), указав только папку `tasks/_fx-1`, пункт GAP из ТЗ и путь результата. Контекст проекта и другие `tasks/` в тесте не читаются.
3. Прогнать проверки формы на результате: `python3 scripts/check_step.py tasks/_fx-1 <файл>`.
4. Сравнить результат с ожиданиями из `Ожидание` в журнале шага.

Фикстура `light` — выдуманная задача про скидку на второй месяц подписки: два файла контекста, ТЗ, разбор материалов и разбор консультанта. Новые фикстуры — отдельной папкой в `tests/fixtures/`; в них только выдуманное.
