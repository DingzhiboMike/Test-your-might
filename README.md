# Полигон гипотез

Система скиллов, которая доводит продуктовую или маркетинговую задачу от сырого запроса до разбора, проверенных на бумаге гипотез или плана живой проверки с готовыми материалами. Каждая идея проходит через контекст продукта, рынка и историю проекта, и ни одно знание не принимается на веру.

Подробно — в документах «Полигон гипотез: описание проекта» и «Система скиллов: спецификация».

## Что внутри

- `AGENTS.md` — инструкции для агента: роли, принципы, правила. Единственный источник правды.
- `CLAUDE.md` — одна строка `@AGENTS.md`: Claude Code читает только свой файл.
- `.claude/skills/` — пятнадцать скиллов. Реестр контрактов — `.claude/skills/orchestrator/registry.md`.
- `methodology/` — указатель GTM-курса, модули курса, протокол работы с вебом.
- `context/` — контекст проекта: материалы о продукте и клиентах.
- `tasks/` — задачи: папки создаёт система.
- Содержимое `context/` и `tasks/` в git не попадает: у каждого, кто скачал репозиторий, свои материалы остаются у него.
- `system-notes.md` — журнал замечаний к системе.

## Где запускать

| Среда | Инструкции | Скиллы |
| --- | --- | --- |
| Claude Code | `CLAUDE.md` → `AGENTS.md` | находит в `.claude/skills/` сам |
| OpenCode | `AGENTS.md` | находит в `.claude/skills/` сам |
| Codex, Cursor и другие | `AGENTS.md` | если среда не нашла скиллы — `AGENTS.md` велит читать их по пути напрямую |

Система писалась под Claude. На других моделях она работает, но качество зависит от того, тянет ли модель длинные инструкции. Разделение «кто строит — тот не проверяет» полноценно работает только в средах с подагентами.

## Как начать

1. Положи в `context/` что есть о продукте и клиентах — что именно, написано в `context/README.md`.
2. `/dispatcher` и задача — или «диспетчер, …», если в среде нет слеш-команд.
3. Согласуй ТЗ. Дальше система идёт сама до сдачи.
4. Провёл живую проверку — возьми заготовки из `tasks/<задача>/results-templates/`, заполни и положи в `tasks/<задача>/results/`. Потом напиши диспетчеру.
