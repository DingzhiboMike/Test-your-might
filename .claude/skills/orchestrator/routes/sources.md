# Шаги-источники

Читается перед первым ходом к источнику данных.

### Источники данных — по выбору

Пункты GAP — не список заданий. **Единый учёт — путь консультанта** (П-k, в валидации — У-k): каждый пункт GAP привязан к пункту пути или стоит «Вне пути» с причиной; отдельных списков дыр и покрытия не ведёшь. После каждого шага — в логе, какие пункты пути закрыты и чем. Генератор строит на том, что есть, проверка по сути сама сверяет внешние факты гипотез с вебом. Источник данных нужен, только когда без него следующее звено будет гадать.

**Путь консультанта — план по умолчанию.** [R-067] Где искать ответ, диспетчер пометил у каждого пункта GAP: `{ответ: контекст / данные / веб / живая}`; после разбора материалов ты это уточняешь. Веб по пункту без «веб» в пометке — только со строкой «Пересмотр:» в заголовке шага. Пункт только с «данные» или «живая» сразу уходит в запрос данных или живую проверку, шаг бюджета не тратится. Каждый П-k из `01-review.md` переводишь в способ закрытия:

| Пункт пути требует | Чем закрывать |
| --- | --- |
| знания, которое есть в контексте или в сети | источник данных — по строкам «Отвечает на / Не отвечает на» в реестре |
| проверки внешнего факта одной гипотезы | проверка по сути, её веб-сверка — отдельный шаг не нужен |
| внутренних данных компании, которых нет в контексте | запрос данных D-N, исполнителя не зовёшь |
| того, что кабинетно не узнать (заплатят ли, сработает ли сообщение) | метод живой проверки — в план или в сдачу |
| уже известного из контекста | ничего: пиши, где это лежит |

После каждого результата пересматриваешь путь: пункт мог закрыться попутно, стать ненужным или потребовать другого способа. Убрать, переставить, добавить — с причиной в логе; молча пропустить нельзя: в сдаче у каждого П-k — исход.

**Перед каждым ходом — вопрос в лог:** «чего не хватает следующему звену и изменит ли ответ гипотезы или вердикт?» Источник зовёшь, если верны все три условия:

1. Без ответа генератор или проверка по сути будут гадать, а не просто знать меньше — **или** это ход за сырьём по линзе (расширяет то, из чего строит генератор).
2. Ответ лежит в `context/` или в вебе; только во внутренних данных — запрос данных (ниже), без исполнителя. Линза ищет не факты о ваших клиентах, а чужие слова, моменты и обходные пути в открытом поле.
3. Это не внешний факт про одну гипотезу: его сверяет проверка по сути.

**Ключевые пункты пути — с достаточностью, а не с лимитом.** [R-068] Ключевые — помеченные консультантом `[ключевой]`; пункт с GAP 1 — всегда. До проверки по сути по каждому ключевому пункту, который закрывается источником, — материал минимум из двух типов каналов (контекст или интервью — и веб при ВЕБ: да), иначе запиши почему. Для остальных числа ходов нет: ход идёт, пока верны три условия, и прекращается, когда критерий ответа выполнен или следующий ход ничего не изменит — одной строкой в лог. «Достаточно N источников» не применяй: это толкает к раннему финалу.

**Плана ходов заранее нет.** [R-069] Следующий ход — после результата предыдущего. Пункт, по которому ход не понадобился, не «пропущен»: исход «закрыт проверкой по сути», «в запросе данных D-N» или «снят — почему».

Кандидатов больше одного — порядок по слоям «Приоритеты» ядра (зависимости, риск, стоимость). Метод для пункта — по строкам «Отвечает на» и «Не отвечает на» в `registry.md`; не отвечает ни один — не подбирай ближайший: исход «системой не закрывается» и путь закрыть (запрос данных или живая проверка).

### Как ставить шаг-источник

Вопрос, канал и критерий ставишь сам — в заголовке шага (см. «Лог») и в шаблоне вызова:

- **Пункт GAP** — из ТЗ **дословно**, целиком, с номером и подпунктами. Пересказ — главная причина блокирующих замечаний проверки смысла: исполнитель отвечает на суженный вопрос, а проверяющий сверяет с ТЗ.
- **Вопрос** — одно предложение с ответом «да / нет», числом, списком или словами клиента; без ответа внутри, не шире и **не уже** пункта: каждая часть пункта видна в вопросе, иначе строка «Сужение:» — что убрано и почему.
- **Канал** — `контекст` (ответ в `context/`, но не вытащен) или `веб` (при ВЕБ: да). Внутренние данные — не канал, а запрос данных.
- **Критерий ответа** — наблюдаемый, до поиска: «не меньше пяти причин ухода, каждая со словами клиента и источником», а не «картина ясна». Не двигается; невыполненный — промах.
- **Бюджет запросов** — в пределах лимита из контракта исполнителя.
- **Уже известно** — id источников, уже покрывающих вопрос, по строке; утверждения команды — «проверяется, не опора».
- **Сверка с реестром** — поле «Когда не вызывать» исполнителя: сказано не звать — другой исполнитель или пункт в незакрытое.

**Запрос данных.** [R-073] Ответ — внутренние данные компании: блок в лог по шаблону методологии (Д · Шаблон запроса), затем в сдачу. «Метрика», «Одна строка» и «Сверка» обязательны; не про метрику — «не применимо» с причиной:

```
Запрос данных D-<N>
Вопрос:      что хотим узнать
Что снять:   выгрузка, расчёт, документ — конкретно
Метрика:     название · формула · числитель · знаменатель · окно (методология, Д · Метрика: определение)
Одна строка: что означает одна строка выгрузки (клиент, заказ, платёж…)
Население:   кто входит, кого исключить, период с границами
Разрезы:     сегменты, периоды, портреты — только те, что меняют решение
Сверка:      контрольное число и какая выгрузка главнее при расхождении (Д · Сверка и расхождения)
Зачем:       какой пункт GAP закрывает и какую гипотезу или решение ограничит
Формат:      колонки и типы; в каком виде вложить в context/
Если данных не будет: дешёвая замена — метод, выборка, срок (10–15 звонков, вопрос из одного пункта в интерфейсе, сверка уже имеющейся выгрузки); чего она не покажет
```

Без персональных данных, с учётом ЗАКРЫТОЕ, только агрегаты. Маршрут запрос не останавливает. **Потолок без замены не сдаётся:** «Если данных не будет» обязательна — чем человек поднимет потолок сам; рядом — чего замена не покажет. Замены идут в бэклог тестов и в «Запросы данных» сдачи.

**Инструмент методологии.** [R-074] Для шага-источника — строка из раздела «Подбирать инструмент» указателя по типу пункта пути (одна, самая близкая; нет — «—») в поле «Инструмент:»; исполнителю — разделы указателя, которые она назвала. Инструмент задаёт рамку проверки, исполнителя выбирает реестр.

**Вопрос шага сверяется скриптом до вызова.** [R-075] Записав заголовок — `python3 scripts/check_log_sources.py tasks/<папка>`; ошибка по невызванному шагу — исправь заголовок до вызова. Перед сдачей — тот же прогон по всему логу.
