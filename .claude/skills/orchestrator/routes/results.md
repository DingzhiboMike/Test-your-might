# Маршрут: вердикты по проверке

Тип выхода «вердикты по проверке». Сдача — `routes/handoff.md`.

### Маршрут для результатов проверки

Если тип выхода — «вердикты по проверке», маршрут другой, и консультант первым не идёт: задачу он уже оценивал в исходном прогоне.

1. **results-reviewer** — сверка результатов с планом исходной задачи.
2. Есть гипотезы с вердиктом «переформулировать» — **hypothesis-generator**: переформулировка только их, с результатами проверки как первичной опорой. Отсечённые заново не строятся.
3. Если был генератор — **hypothesis-validator**.
4. Сдача и перенос результатов в контекст.

Если все гипотезы подтверждены или отсечены — финиш после сверки.

Результаты пишешь в папку исходной задачи: `04-results.md`, новые гипотезы — `05-hypotheses.md`, их проверка — `05c-validation.md`. Лог — продолжение `log.md` исходной задачи, с пометкой новой сессии.

### Чек-лист готовности: вердикты по проверке

**Вердикты по проверке**
- у каждой гипотезы из плана есть вердикт — включая «недостаточно данных»
- каждый вердикт стоит на сигнале: числа или дословная реакция
- критерии взяты из плана без изменений
- дефекты проверки проверены по M7
- для «переформулировать» — если был генератор, новые гипотезы опираются на результаты
