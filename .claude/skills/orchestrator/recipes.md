# Рецепты оркестратора

Стартовые наборы шагов по типу выхода и уровню нагрузки. Читается один раз, сразу после выбора профиля. Рецепт — не маршрут: он говорит, с чего начать и по какому признаку добавить или убрать шаг. В `log.md` перед ШАГОМ 1 одна строка: `РЕЦЕПТ: <тип выхода> · <уровень>; отклонения: нет / что и почему`. Отклонение допустимо, если ТЗ или результат шага его требуют.

Рецепты собраны из прогонов; после новых прогонов дополняются по расходу из служебной части сдачи и по строке «что обещал уровень и что сделано».

## Общие правила подбора шагов (работают на любом уровне)

1. **Один ключевой пункт GAP — один источник данных, и каждый шаг привязан к пункту дословно.** В заголовке шага: пункт GAP целиком, вопрос с наблюдаемым критерием ответа, бюджет запросов, «зачем» одной строкой.
2. **Какая линза какому вопросу.** Выбирай по тому, что спрашивает ключевой пункт, а не по привычке:
   - «чем заменяют», «с кем конкурируем», «почему выбирают не нас» → `alternatives-analyst`;
   - «кто это, какие роли, кто платит или решает» → `target-audience-analyst`;
   - «какими словами говорят, насколько остро, где обсуждают, какие правила площадок» → `market-analyze`;
   - «когда клиент готов, что запускает поиск» → `customer-path`, только если у задачи есть момент выбора или покупки;
   - «сколько, хватит ли на цель» → `market-sizing`, только если в цели есть число.
3. **Не звать линзу нужно с причиной, привязанной к пунктам GAP.** «Момент переключения не касается выбора применения» — причина; «чтобы сэкономить шаги» — нет. Если лимит линз по профилю меньше подходящих, оставляй линзы под ключевые пункты с наибольшей ценой ошибки, остальные — «не нужно: ограничение профиля».
3б. **Шаг-источник, который закрывает и другие ключевые пункты,** помечается строкой «Закрывает также: GAP k» в заголовке шага; `check_effort` засчитывает ход по этим пунктам тоже.
4. **Шаг без ожидания не запускается.** В заголовке «Ожидание» формулируется наблюдаемо (какой файл, что в нём по критерию), по нему потом сверяется «Результат: совпал / промах».
5. **`route.py done` — только после возврата исполнителя.** Перезапрос после ошибок проверок открывается одной командой `route.py retry tasks/<папка>` (заново открывает последний шаг с ошибками, ту же роль и артефакт); пока исполнитель не вернул управление, шаг не закрывай. Без открытого шага хук записи не пустит исполнителя в артефакт.
6. **На уровнях light и work без контекста** в первой строке сдачи: «без ваших данных выводы — гипотезы, не факты», и блок «Что нужно, чтобы двигаться дальше» первым, если все вердикты «сузить / не держится».
7. **Сплошное «сузить» при forecast=off.** Не включай Нострадамуса сам: предложи человеку поднять уровень до work и скажи, что он добавит (версии по ключевым вопросам и новые идеи) и сколько это примерно ждать.

## Тип выхода «гипотезы»

| Шаг | light | work | strict |
| --- | --- | --- | --- |
| Разбор материалов | не нужен, если контекст — только публичные ссылки, прочитанные диспетчером (они в `sources.csv`) | `context/` и источники из ссылок запроса | `context/` и источники из ссылок запроса; карта документов при 8 и более файлах |
| Консультант | да | да | да |
| Линзы | 1 — под ключевой пункт с наибольшей ценой ошибки | 2 — под два ключевых пункта | 3, по правилу выше |
| Генератор | ширина: длинный список, затем глубина | обычный (3–5 гипотез), ширина по ТЗ | обычный |
| Проверка по сути | по методологии, без веба | с веб-сверкой внешних фактов | с веб-сверкой, запросы на опровержение |
| Проверка смысла | нет | нет | да, после проверки по сути, с исправлением |
| Нострадамус и отсев идей | нет | да | да |
| Позиция и бэклог | да | да | да |
| Аудит | нет | нет | да, до сдачи |
| Опоры | без сверки (К5) или ссылки (К4) | ссылки | цитаты со сверкой |

Когда добавлять шаг сверх рецепта:
- ключевой вывод стоит на одном источнике, а ошибка дорогая → веб-сверка (work) или проверка смысла (strict) именно этого артефакта;
- проверка по сути нашла противоречие основанию ТЗ → остановка и возврат к диспетчеру, а не ещё один источник.

Когда убирать шаг:
- линза, на которую по пункту GAP уже отвечает карта знания (укажи где);
- второй вызов проверки по тем же гипотезам без нового входа.

## Другие типы выхода (коротко)

- **Разбор:** консультант; на light — финиш, на work/strict — проверка по сути по основному допущению.
- **Валидация:** карта утверждений консультанта → проверка по сути; light — без веба и усиления, work — с вебом, strict — полный маршрут v1 с проверкой смысла документа.
- **Исследование:** линзы под вопросы отчёта, отчёт; light — без проверки смысла, strict — с ней и с аудитом.
- **Вердикты по проверке:** сверка результатов с планом; уровень не меняет маршрут.

## Что считать успешным прогоном

Сделано то, что обещал уровень («что будет сделано», «что получите»), вызовы в пределах ЦЕНА, в сдаче названо, чего профиль не покрыл, и человек знает, что запускать. Расхождение больше трети по вызовам — причина в служебной части сдачи.
