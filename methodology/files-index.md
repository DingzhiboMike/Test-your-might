# Указатель файлов и скриптов

Полный текст раздела «Где что лежит» из `AGENTS.md`. Открывай, когда нужен конкретный файл, скрипт или служебный файл задачи.

- `methodology/tools-index.md` — указатель инструментов методологии. Скиллы ссылаются на него просто как `tools-index.md`.
- `methodology/web-protocol.md` — протокол работы с вебом: где искать, как отбирать отчёты, запрос на опровержение, метки уверенности. Скиллы ссылаются на него как `web-protocol.md`.
- `methodology/modules/` — сами модули методологии (M0–M8, M11–M13, Э, Д, К, О, П, Ж, С) и приложение к M2. Указатель ссылается на модуль по номеру и заголовку раздела: открой файл модуля с этим номером и найди раздел по заголовку.
- `context/` — контекст проекта: интервью, выгрузки, описания сегментов. Кладёт человек до запуска. Скиллы читают, но не пишут сюда.
- `context/from-tasks/` — материалы источников из прошлых задач. Сюда пишет только оркестратор — автоматически, в конце маршрута, с шапкой происхождения. Что перенесено, видно в сдаче; лишнее человек удаляет сам. Только `src-*` — разборы интервью, записки по рынку, профили ЦА, карты альтернатив, оценки рынка, пути клиента — и результаты живой проверки из `04-results.md`. Разбор `src-*` — это материал системы, а не случившееся: в новой задаче он регистрируется как `--ctx-type system`, а опорой служит только дословный фрагмент исходного источника, который в нём приведён. Оценки системы внутри `src-*` опорой не бывают никогда.
- `system-notes.local.md` — локальный журнал замечаний к системе из сдач: его дописывает оркестратор, в git он не попадает. `system-notes.md` — журнал правок системы в репозитории: пишет только человек, когда правит систему, и только словами о системе — без названий задач, продуктов, партнёров, сегментов и чисел из задач.
- `tasks/<задача>/sources.csv` и `tasks/<задача>/sources/raw/` — реестр источников задачи и их сырой текст. Пишется только `scripts/add_source.py`, порядок — в `web-protocol.md`, п. 2б.
- `scripts/` — проверки, которые не зависят от честности исполнителя: `add_source.py` (реестр), `check_quotes.py` (цитаты против сырого текста), `check_artifact.py` (артефакт шага, периметр записи, ответы на замечания проверки смысла), `list_unused.py` (найдено на шаге, но не процитировано), `add_number.py` и `check_numbers.py` (реестр чисел: производные пересчитываются, фрагмент проверяется в источнике), `trust_map.py` (счёт опор для карты доверия), `check_private.py` (персональные данные в артефактах и в логе), `check_step.py` (все проверки после шага одной командой и одной строкой для лога, со счётчиками цитат и корней), `check_log_sources.py` (в задачах на гипотезы перед генератором есть блок ЛИНЗЫ с решением по каждой линзе; у каждого шага-источника в логе есть пункт GAP дословно, вопрос не уже пункта, зачем и что уже известно; у запроса данных — дешёвая замена), `check_path.py` (каждый пункт GAP привязан к пути консультанта, варианты решения покрыты, у каждого пункта пути есть исход; с `--tz` — у каждого пункта GAP пометка, где ответ, и ВЕБ с ними согласован), `check_effort.py` («мало данных» — не выход: ключевой пункт с ответом в вебе не сдан без хода к источнику, при сплошном «сузить» сдача начинается с запроса данных, идей в сдаче — не больше ёмкости + 1), `check_forecast.py` (режим Нострадамуса совпадает с условием; в режиме с новыми идеями — не меньше пяти, у каждой «не повторяет», «уточнит», первый шаг и «на чём» — поле источника с id или новый сбор; рамка сверена; по каждому ключевому вопросу лучшая версия, альтернатива, что различит и следующий шаг — не «нет данных»), `check_ideas.py` (отсев новых идей Нострадамуса: вердикт по каждой, поле «Возражения», выполнимость первого шага, у живых — данные для следующего раунда, снятые — с причиной), `check_rehearsal.py` (пробный прогон на синтетике меняет эксперимент и решение: статус у каждого теста, ответ на каждое следствие в бэклоге или плане), `check_knowledge.py` (разбор материалов прочитал каждый файл контекста и по каждому пункту GAP написал, чего нет), `map_docs.py` (картография документов, слой скрипта: нумерует строки текста, размечает теги «число», «срез», «продукт», «риск», кэширует по хэшу), `map_summary.py` (сводка карты для диспетчера без модели: таблица документов, что не читается, срезы, строки про продукт) и `build_model.py` (модель предмета: матрица «группа × признак», надёжность клеток считает скрипт по правилам, пустые и слабые клетки), `rank_impact.py` (важность документов по формуле, кандидаты на углубление с лимитом по тиру), `check_chain.py` (у каждой гипотезы клетка модели, рамка продукта со статусом «есть», размер группы), `check_rank.py` (порядок направлений в позиции выводится из надёжности клеток), `check_map.py` (досье документов: блок на каждый файл, поля, цитаты адресны и дословны по номеру строки, строки с числами учтены или отброшены с причиной, оценки важности в досье нет), `handoff_index.py` (раздел сдачи «Что лежит в папке задачи»: таблица файлов задачи с описаниями; служебная часть сдачи лежит в `08-service.md`), `check_readable.py` (документы для людей — брифы, позиция, бэклог тестов, сдача: без слов системы и внутренних номеров, под именами из реестра), `check_fresh.py` (старый веб-источник процитирован с годом), `check_long_list.py` (отсев длинного списка в режиме ширины по правилам, записанным заранее), `sensitivity.py` (чувствительность формулы из реестра чисел), `polygon.py` (полигон без нейросети: выдуманные отчёты об экспериментах, транскрипты интервью с заложенными сигналами и строки документов с известной разметкой, кейс с заложенными направлениями для генератора — с ключом ответов и сверкой), `check_publish.py` (перед отправкой на GitHub: имена, партнёры и коды из задач не уходят в репозиторий; хук `scripts/git-hooks/pre-push`, подключается командой `git config core.hooksPath scripts/git-hooks`), `hooks/guard_writes.py` (запрет правок системы и реестра по ходу задачи; подагентам — только скрипты системы и чтение в Bash, сеть — только ролям с сетью), `hooks/stop_check.py` (перед окончанием ответа сам прогоняет проверку цитат по задачам последних 12 часов и один раз не даёт закончить, если есть ошибки) , `hooks/trace.py` (трасса: по транскриптам считает вызовы, токены, время и фактическую модель каждого исполнителя и основной сессии) — все три подключены в `.claude/settings.json`, `trace_summary.py` (сводка расхода задачи, строка «Расход» за шаг, версия системы для шапки лога), `cost_estimate.py` (строка ЦЕНА для ТЗ: вызовы маршрута — свободная часть, резерв, потолок — и токены по трассам прошлых задач; с `--left` — сколько осталось), `roles.py` (таблица ролей: модель, сеть, инструменты; из неё — описания агентов в `.claude/agents/` и права подагентов в хуке записи), `data_block.py` (блоки данных в артефактах: JSON по схеме вместо текста, который ловят регулярками, — ответы на проверку смысла, отсев идей, следствия пробного прогона), `route.py` (маршрут в коде: `state.json`, регистрация шага, периметр по хэшам, обязательные шаги типа выхода, готовность), `hooks/step_gate.py` (исполнитель не сдаёт артефакт с ошибками проверок, пока один раз не попробовал их исправить), `audit_sample.py` (выборочный аудит: три случайных места на итоговый артефакт, воспроизводимо; оценки «держит / не держит / подогнано» — блоком данных в `audit.md`), `rules.py` (реестр правил `methodology/rules.csv`: id в тексте, откуда правило и чем проверяется, сколько раз меняло решение по логам; новые правила без прогона-источника и регрессии не проходят), `check_size.py` (размер инструкций в токенах: ядро оркестратора, маршруты, скиллы, загрузка на тип выхода — с порогами), `selftest.py` (самопроверка всех скриптов — запускать после любой правки в `scripts/`). Чтобы править саму систему, создай в корне пустой файл `.polygon-dev` и удали его после.
- `tasks/<задача>/` — папка задачи. Её создаёт диспетчер, файлы в неё сохраняет оркестратор. Результаты живой проверки человек кладёт в `tasks/<задача>/results/`. Служебные файлы картографии и модели: `map/` (пронумерованный текст и теги, пишет `map_docs.py`), `00d-map.md` (досье документов), `00m-schema.txt`, `00m-cells.csv`, `00m-model.md` и `00m-model.json` (модель предмета; `.md` и `.json` пишет `build_model.py`), `00r-limits.md` (рамки продукта), `00i-impact.md` (важность документов, пишет `rank_impact.py`), `02e-trace.md` (след позиции, не для человека). Расход: `trace.jsonl` и `trace-main.json` (пишет хук трассы), `checks/cost.json` (итог при сдаче, пишет `trace_summary.py --save`).
